# Git Visualizer — инструкция пользователя

Инструкция описывает работу с готовым приложением, запущенным из исходников.
Установка и запуск описаны в [README](README.md); известные ограничения — там же,
в разделе «Известные ограничения MVP».

## 1. Перед началом

- Приложение работает на Windows 10/11 x64 и требует Python 3.12+ и Git 2.23+ в `PATH`.
- Запуск: `.venv\Scripts\python.exe -m git_visualizer.main` или команда `git-visualizer`.
- При запуске приложение проверяет Git. Если Git не найден или его версия ниже 2.23,
  стартовый экран показывает сообщение с предложением установить или обновить Git
  (<https://git-scm.com/downloads>). Приложение при этом не закрывается.
- Приложение не запрашивает и не хранит пароли и токены: авторизация выполняется
  штатными средствами Git (SSH-ключи, Git Credential Manager, credential helpers).

## 2. Открытие репозитория

1. На стартовом экране нажмите **«Открыть репозиторий»**.
2. Выберите папку проекта в стандартном диалоге.
3. Если выбрать вложенную папку внутри репозитория, приложение само найдёт и откроет
   корень репозитория.
4. Ранее открытые репозитории доступны в списке недавних на стартовом экране —
   один клик по записи открывает репозиторий заново.

Если папка не подходит, приложение показывает понятное сообщение и остаётся на
стартовом экране:

- папка не найдена или выбран файл вместо папки;
- в папке нет Git-репозитория;
- выбран каталог `.git` или bare-репозиторий (bare-репозитории не поддерживаются).

Чтобы закрыть репозиторий и вернуться на стартовый экран, нажмите **«Закрыть»** в
верхней панели. Данные репозитория при этом не меняются.

## 3. Обзор главного окна

- **Верхняя панель:** название приложения, имя репозитория (полный путь — в подсказке),
  текущая ветка (или `detached HEAD`, или пометка «коммитов нет»), список настроенных
  remote, кнопки **Fetch**, **Pull**, **Push**, **«Настройки remote»**, **«Обновить»**,
  **«Закрыть»** и индикатор выполнения операции.
- **Левая панель «Ветки и remote»:** локальные и remote-tracking ветки, текущая ветка
  выделена, форма создания новой ветки, кнопка **«Переключиться»**.
- **Центр:** интерактивный граф истории.
- **Правая панель «Детали коммита»:** сведения о выбранном коммите и список изменённых файлов.
- **Нижняя панель «Изменения»:** списки Unstaged/Staged, кнопки Diff, Stage/Unstage,
  Commit, Discard Changes и обновление статуса.

Панели можно расширять и сужать мышью за разделители. Если панель «Изменения» или
область графа полностью уведена за край, на освободившемся месте появляется кнопка
возврата панели.

## 4. История и граф

- Список коммитов строится по всем локальным и remote-tracking веткам и `HEAD`, в
  топологическом порядке (потомки всегда выше родителей). Служебные коммиты stash в
  граф не попадают.
- **Выбор коммита** — один клик по узлу. Узел выделяется, правая панель показывает
  подробности. Наведение курсора показывает краткую подсказку (hash, автор, сообщение, дата).
- **Метки веток** отображаются рядом с узлами: локальные и remote-tracking. Текущая
  ветка выделена надписью `HEAD → имя`, заливкой и кольцом узла; удалённые ветки —
  пунктирной рамкой. Цвет дорожки помогает различать линии, но не является единственным
  признаком ветки.
- **Масштаб** — колесо мыши: масштаб меняется вокруг точки под курсором.
- **Панорамирование** — перетаскивание мышью.
- **«Вписать граф»** (или `Ctrl+0`) — подобрать масштаб и положение так, чтобы была
  видна вся загруженная история.
- **Ограниченная история.** Приложение загружает последние коммиты в пределах лимита
  (по умолчанию 3000; лимит меняется в «Настройках…»). Если история в лимит не
  поместилась, под графом появляется уведомление «Показаны последние N коммитов — в
  репозитории есть более старая история» и кнопка **«Загрузить ещё»**: она добавляет
  следующую страницу более старых коммитов, не сбрасывая выбранный коммит и положение
  графа. Пока загружена не вся история, уведомление остаётся; после последней страницы
  оно исчезает.
- Если коммитов нет, в центре показывается состояние «История пуста», а панель деталей
  сообщает, что коммитов пока нет.

## 5. Детали коммита и diff

В правой панели для выбранного коммита показаны:

- полное сообщение коммита;
- с чем сравниваются изменения: root-коммит — с пустым деревом, merge-коммит — с
  **первым** родителем, обычный коммит — со своим родителем;
- короткий и полный hash, автор и его дата, committer и дата коммита, refs;
- список изменённых файлов со статусами: добавлен, изменён, удалён, переименован,
  скопирован, тип изменён.

Чтобы посмотреть diff, выберите файл в списке. Diff открывается большой панелью поверх
окна; закрыть её можно крестиком **✕** или клавишей `Esc`. В заголовке панели указано,
с чем сравнивается файл (для merge — первый родитель). Добавленные и удалённые строки
подсвечиваются разными цветами. Для бинарного файла выводится сообщение, что текстовый
diff недоступен; слишком большой diff обрезается с сообщением об этом.

## 6. Рабочая директория: панель «Изменения»

Панель показывает два списка:

- **Unstaged** — изменения рабочей директории, ещё не добавленные в индекс (включая
  untracked-файлы и конфликтующие файлы с пометкой «конфликт»);
- **Staged** — изменения, уже добавленные в индекс.

Один файл может находиться в обоих списках: например, файл добавлен в индекс, а затем
изменён ещё раз.

Действия:

- **Выбор файла** — один клик по строке (файл только выбирается, diff сам не открывается).
- **«Diff»** в заголовке панели — открыть diff выбранного файла для его секции
  (staged — индекс относительно HEAD, unstaged — рабочая директория относительно индекса).
  Для untracked-файла diff недоступен до добавления в индекс, приложение показывает пояснение.
- **Stage / Unstage** — добавить выбранный файл в индекс или убрать его оттуда.
  Изменения в рабочей директории при этом сохраняются.
- **Stage All / Unstage All** — массовая операция для всей секции. Перед выполнением
  приложение показывает подтверждение: количество файлов, категории и (в «Подробнее»)
  список. По умолчанию выбрано «Нет». Конфликтующие файлы массовыми операциями не
  затрагиваются.
- **Discard Changes** — отменить все незакоммиченные изменения выбранного файла.
  Операция необратима и всегда требует подтверждения; для untracked-файла удаляется
  сам файл с диска. Конфликтующие файлы отменить так нельзя.
- **«Обновить»** — заново запросить состояние рабочей директории.

Статус обновляется автоматически после stage/unstage, коммита, переключения ветки и
сетевых операций. Если был открыт diff файла, после Stage/Unstage он переключается в
новую секцию.

## 7. Создание коммита

1. Добавьте в индекс файлы, которые должны войти в коммит (Stage / Stage All).
2. Нажмите **«Commit»** в заголовке панели «Изменения». Кнопка доступна только при
   наличии staged-файлов.
3. В окне **«Новый коммит»** введите сообщение. Commit в окне заблокирован, если
   сообщение пустое или состоит из пробелов; подсказка показывает, сколько файлов
   войдёт в коммит.
4. Нажмите **«Commit»**. `Esc` или **«Cancel»** закрывают окно без коммита.

В коммит попадают **только** staged changes: unstaged и untracked файлы остаются в
рабочей директории. После успешного коммита окно закрывается, сообщение очищается, а
история, граф, ветки и статус перезагружаются. Если Git отказал (например, не настроен
автор коммита, сработал hook или есть неразрешённые конфликты), окно остаётся открытым
с введённым текстом, показывается понятное сообщение и технические подробности.

## 8. Ветки

- Список веток — в левой панели: сначала локальные, затем remote-tracking. Текущая
  ветка выделена; у локальных веток в подсказке виден upstream.
- **Создание:** введите имя в поле «Новая ветка» и нажмите **«Создать»**. Ветка
  создаётся от текущего `HEAD` и сразу становится текущей. Чтобы создать ветку от
  выбранного в графе коммита, отметьте «Создать от коммита <hash>» и нажмите «Создать».
- **Переключение:** выберите локальную ветку в списке и нажмите **«Переключиться»**.
  Если в рабочей директории есть незакоммиченные изменения, приложение предупреждает;
  безопасность обеспечивает сам Git — при конфликте он отказывает, ничего не удаляя и
  не перезаписывая.
- Remote-tracking ветки отображаются, но переключиться на них нельзя (создание
  локальной tracking branch в MVP не входит).
- Ошибки (недопустимое имя, занятое имя, ветка не найдена, конфликт изменений)
  показываются понятным сообщением.

## 9. Remote и синхронизация

### Настройка remote

1. Нажмите **«Настройки remote»** в верхней панели.
2. В окне со списком remote доступны действия **«Добавить»**, **«Изменить»**,
   **«Удалить»**, **«Закрыть»** (они же в контекстном меню списка).
3. При добавлении или изменении укажите имя remote и URL: поддерживаются HTTPS, SSH и
   локальный путь. Изменение имени выполняется средствами Git, вместе с настройками
   веток и remote-tracking refs.
4. Удаление требует подтверждения и затрагивает только локальную конфигурацию Git:
   файлы проекта и репозиторий на сервере не меняются.

### Fetch, Pull, Push

- В верхней панели выберите remote из списка (для Fetch и первого Push).
- **Fetch** получает изменения выбранного remote; обновляются remote-tracking ветки и граф.
- **Pull** доступен только в репозитории с коммитами и при обычном (не `detached`) HEAD.
  Выполняется как `git pull --ff-only`: если ветки разошлись, ничего не меняется и
  показывается сообщение, что fast-forward невозможен; merge и rebase не выполняются.
- **Push** отправляет текущую ветку в её upstream. Если upstream не настроен, приложение
  предложит выбрать remote и выполнит первый Push с `--set-upstream`.
- Ход и итог операции отображаются в верхней панели; после успеха или ошибки данные
  репозитория перезагружаются.
- Force push недоступен. Ошибки сети, прав, авторизации и non-fast-forward показываются
  понятным сообщением, полный вывод Git — в подсказке или разделе «Подробнее».

## 10. Обновление данных и настройки

- **«Обновить»** в верхней панели перезагружает историю, ветки, refs и remote;
  **«Обновить»** в панели «Изменения» — статус рабочей директории.
- **«Настройки…»** на стартовом экране открывают диалог, где можно изменить лимит
  загрузки коммитов (от 100 до 20 000, шаг 100; по умолчанию 3000). Новое значение
  применяется к следующим загрузкам истории. Этот же лимит задаёт размер страницы,
  которую добавляет кнопка «Загрузить ещё».
- Размер и положение окна, состояние разделителей панелей и положение графа (масштаб и
  центр) сохраняются автоматически и восстанавливаются при следующем запуске. Положение
  графа хранится отдельно для каждого репозитория.
- Список недавних репозиториев ограничен 10 записями; перемещённая или удалённая папка
  удаляется из списка с сообщением, приложение остаётся на стартовом экране.

## 11. Ошибки и технические подробности

- Ошибка Git или файловой системы не закрывает приложение: показывается короткое
  русское сообщение с объяснением и, если есть, кнопка/раздел **«Подробнее»** с командой,
  кодом завершения, stdout и stderr.
- После неудачной операции интерфейс обновляет состояние, чтобы не показывать устаревшие
  данные.
- Если Git не найден или его версия ниже 2.23, приложение показывает инструкцию по
  установке/обновлению на стартовом экране.

## 12. Горячие клавиши

- `Ctrl+0` — «Вписать граф».
- `Esc` — закрыть панель diff или окно сообщения коммита.

## 13. Ограничения

Полный список ограничений MVP приведён в [README](README.md), раздел «Известные
ограничения MVP». Кратко: нет merge/rebase и разрешения конфликтов, Pull только
fast-forward, нет force push, удаления веток, тегов, stash, клонирования, сборки `.exe`,
темы и иконок; история ограничена лимитом загрузки; авторизация GCM/SSH и работа на
Git 2.23 требуют ручной проверки.
