# Git Visualizer

Настольный Git-клиент для Windows с интерактивным графом коммитов.
Стек: Python 3.12+, PySide6, системный Git CLI (Git 2.23+).

Приложение открывает локальный Git-репозиторий и показывает историю всех локальных
и remote-tracking веток, детали коммитов, diff, состояние рабочей директории и
позволяет выполнять основные повседневные операции без терминала.

> Статус: MVP реализован и запускается из исходников. Сборка `.exe` отложена
> (см. «Сборка Windows-приложения» и «Известные ограничения MVP»). Ручные проверки
> авторизации GCM/SSH и работы на минимальной версии Git ещё не выполнены.

## Возможности

- открытие репозитория по папке (вложенная папка открывает корень репозитория), список недавних репозиториев;
- история всех локальных и remote-tracking веток и `HEAD` в топологическом порядке, настраиваемый лимит загрузки с догрузкой более старой истории;
- интерактивный граф: root-, обычные и merge-коммиты, метки веток, выделение текущей ветки, масштабирование колесом, панорамирование, «Вписать граф»; большие истории строятся порциями, не блокируя окно;
- детали коммита (полный и короткий hash, автор, даты, сообщение, refs) и список изменённых файлов со статусами;
- diff файла коммита и файла рабочей директории (staged/unstaged) с подсветкой добавленных и удалённых строк, сообщением о бинарных файлах и ограничением объёма;
- панель Changes: staged, unstaged, untracked и конфликтующие файлы; Stage/Unstage для файла, Stage All/Unstage All;
- создание коммита только из индекса, сообщение в отдельном окне;
- создание и переключение локальных веток;
- remote: список, добавление, переименование, изменение URL и удаление; Fetch, Pull (только fast-forward) и Push (в upstream либо первый Push с `--set-upstream`);
- настройки через `QSettings`: недавние репозитории, размер и положение окна и панелей, положение графа отдельно для каждого репозитория, лимит загрузки коммитов;
- долгие операции выполняются в фоновых задачах, Git-команды запускаются без `shell=True`.

Подробное описание работы с приложением — в [инструкции пользователя](USER_GUIDE.md).

## Требования

- Windows 10 или Windows 11 x64 — основная целевая платформа;
- Python 3.12 или новее;
- Git 2.23 или новее в `PATH`. Если Git не найден или его версия ниже 2.23, приложение
  показывает сообщение с предложением установить или обновить Git
  (<https://git-scm.com/downloads>).

## Установка

Windows (PowerShell), из корня репозитория:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -e ".[dev]"
```

Если PowerShell блокирует `Activate.ps1`, разрешите скрипты только для текущей сессии:
`Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned`.

Linux / macOS (для разработки; целевой платформой остаётся Windows):

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -e ".[dev]"
```

## Запуск из исходников

```bash
python -m git_visualizer.main
```

Либо командой, созданной при установке пакета: `git-visualizer`.

## Тесты

```bash
pytest
```

Тесты используют платформу Qt `offscreen`, поэтому окна при запуске не открываются.

- Unit-тесты проверяют парсеры Git-вывода, доменные модели, сервисы, виджеты, фоновые
  задачи и границы слоёв (AST-тесты).
- Integration-тесты создают временные репозитории и выполняют реальные Git-команды:
  линейная история, ветки и merge, detached HEAD, репозиторий без remote, Unicode и
  пробелы в путях, многострочные сообщения, staged+unstaged одновременно, untracked,
  конфликты, недействительные папки, а также Fetch/Pull/Push на локальном bare-remote.

## Сборка Windows-приложения

Сборка `.exe`/portable-версии через PyInstaller **отложена** и в текущую приёмку MVP
не входит (решение 38): приложение запускается из исходников по инструкции выше.
Когда сборка понадобится, потребуется добавить PyInstaller, файл спецификации,
шаги сборки и инструкцию запуска готовой сборки — это отдельная задача.

## Известные ограничения MVP

- **Merge, rebase, cherry-pick и разрешение конфликтов не реализованы.** Конфликтующие
  файлы (unmerged) только отображаются: массовые Stage/Unstage их не затрагивают, а
  коммит при конфликтах завершается ошибкой Git с понятным сообщением.
- **Pull выполняется только с `--ff-only`.** Если ветки разошлись, ничего не меняется;
  альтернативные действия (merge, rebase, force) не предлагаются.
- **Push не форсируется**: force push и его варианты недоступны.
- **Удаление веток не реализовано**, как и создание локальной tracking branch из
  remote-tracking ветки (для MVP это допускается).
- **Теги и stash не отображаются**; служебные stash-коммиты в граф не попадают.
- **Клонирование репозитория, amend, revert, cherry-pick, сравнение произвольных
  коммитов** не реализованы.
- **Bare-репозитории не поддерживаются** — приложение сообщает об этом и не открывает их.
- **История ограничена лимитом** (по умолчанию 3000 коммитов, диапазон настройки
  100–20 000). Если история не помещается в лимит, приложение сообщает об этом и
  показывает кнопку «Загрузить ещё», которая догружает следующую страницу более старых
  коммитов (FR-HIST-07).
- **Diff не разбивается на hunks**; очень большие diff обрезаются (200 000 символов) с
  сообщением, для бинарных файлов текстовый diff недоступен.
- **Discard Changes** (отмена незакоммиченных изменений выбранного файла) —
  дополнительная функция вне базового MVP: необратима, всегда требует подтверждения, а
  для untracked-файла удаляет файл с диска.
- **Тема интерфейса и иконки не реализованы** (отложено, решение 39): используются
  встроенные стили и текстовые подписи.
- **Сборка `.exe` отложена** (решение 38).
- **Не проверено вручную:** авторизация Fetch/Push через Git Credential Manager и SSH на
  Windows; работа на минимальной версии Git 2.23.
- **Авторизация** выполняется штатными средствами Git; приложение не запрашивает и не
  хранит пароли, токены и приватные ключи.
